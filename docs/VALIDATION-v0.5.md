# v0.5 validation and limits

Measured on the development Linux CPU, not the user's OptiPlex. The central
finding is **mixed**: the final short practice run increased protected time and slightly reduced damage
in dense practice layouts, but construction reward and full-habitat food intake decreased. This release provides new learning capabilities; it does not
demonstrate reliable shelter planning, a faster time to mastery, or an advantage
over v0.4 in a matched architecture comparison.

## Checks

- 75 Python tests, including the previous ecology/learning/streaming checks.
- 7 JavaScript motion-buffer tests.
- Separate typed sensor channels distinguish a block from a world boundary and
  hide the farther surface. Real input currents change the named neuron banks.
- Cover memory records occupied sites only, follows body motion, expires and
  clears stale sites on return. Threat memory does not follow unseen predators.
- A deliberate learned backward choice is obeyed with cover ahead. The learned
  Rest action settles spiking motor output without snapping body coordinates.
- Real experienced reward trains the chosen action's shared features; similar
  geometry shares that learning. Replay cannot modify food/water motor tables.
- Cover potential passes discounted-cycle and stationary-camping checks. Existing
  construction tests reject closed boxes, boundary-only "shelters" and repeat credit.
- Checkpoint resume is exact with replay, RNG, cover memory and actions in flight.
  Frozen trials leave learned weights, counters and replay contents unchanged.
- v4 migration retains block layout, all old action columns and goal values,
  synapses, needs and time, with an original backup and no extra habitat expansion.
  v1–v3 migration and automatic-life retention tests also pass.
  A checkpoint generated by the actual published v0.4 code was also loaded;
  old action values, synapses, block layout and original archived bytes matched.
- Practice leaves its source untouched. Adoption retains the live brain's newer
  unrelated motor skills and recurrent weights.

## One bounded learning run

Reproduce without using live data:

```bash
.venv/bin/python scripts/validate-cover-learning.py --seed 2201 --output /tmp/cover-learning.json
```

Seed 2201, 40 episodes × 30 simulated seconds: 20 loose-material episodes, then
20 with a predator. Default v0.2 food-trained source, new shelter weights zero.
Training accumulated 2,736 building feature updates and 2,103 use-cover feature
updates (including replay). Source fingerprint remained unchanged.
No candidate is bundled, selected from the audit, or auto-adopted.

Candidate and original then run frozen with shaping off on five new dense-material
layouts (4002208, 4002311, 4002414, 4002517, 4002620), 30 seconds each:

| Mean measure | Starting model | After practice |
| --- | ---: | ---: |
| Survived full trial | 5/5 | 5/5 |
| Damage | 21.0 | 18.0 |
| Food per simulated minute | 7.6 | 6.4 |
| Construction reward earned | 1.00 | 0.20 |
| Protected seconds | 1.37 | 3.04 |
| Material distance pushed | 5.09 | 2.73 |

A second frozen audit uses the normal 144 × 90 scarce habitat with water and one
predator, different seeds (5002212, 5002315, 5002418, 5002521, 5002624):

| Mean measure | Starting model | After practice |
| --- | ---: | ---: |
| Survived full trial | 5/5 | 5/5 |
| Damage | 0.0 | 0.0 |
| Food per simulated minute | 11.2 | 8.4 |
| Construction reward earned | 1.50 | 0.20 |
| Protected seconds | 0.50 | 0.00 |
| Material distance pushed | 3.90 | 0.96 |

Total measured runtime was approximately 177.6 seconds on this development CPU,
including the audits and with other verification work running. This is not an
OptiPlex performance estimate. [Raw records](cover-learning-v0.5.json) include all
trials, seeds, counters and timing. These are small samples and short lives; they
cannot establish generalization or sustained survival. Damage can improve through
foraging/goal choices, avoiding obstacles, or using naturally occurring cover.
Neither protected time nor construction reward alone proves deliberate building.

The earlier development run (seed 1201) is retained in
[development records](cover-learning-v0.5-development.json). It predates connecting
remembered threats to the goal selector and escape context. Its decreased
construction reward was also reported, not used to select a pretrained candidate.
The final run used a new training seed and new audit seeds after that correction;
no further behavioral tuning followed its audit. This is not a controlled ablation
of memory, replay or the Rest action.

`bash setup.sh` successfully built and installed editable v0.5.0. The build uses
the normal isolated setuptools environment; no runtime dependency changed.

## Browser

Real Chromium at desktop 1440 px and mobile 390 px exercised the new sensor rows,
memory/replay status, the shelter-practice form, a real two-episode worker job,
paired practice/full-habitat results and protection against adoption while alive.
Previous automatic-life, freeze retention, pause and stage controls still worked.
No JavaScript errors or horizontal overflow; screenshots inspected at both sizes.

A short moving sample recorded 19.7 geometry updates/s and 60 rendered frames/s,
averaging 2,813 bytes per motion packet. Telemetry carries the extra sensors, not
the fast geometry frames. Paused windows, CPU load and browser/device performance
can reduce measured frame rates. No new runtime dependency or GPU is required.

## What remains unproven

Multi-step construction, intentional occupancy after building, useful homes across
lifetimes, and long survival amid scarce resources require longer experiments and
further design. This implementation has no world model or placement planner.
Adopt a practice candidate only if its comparisons fit the behavior you value;
this example would **not** be evidence to adopt for improved construction.
